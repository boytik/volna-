## 1. Что это за продукт

«Волна» — мобильное приложение психологической самопомощи для родителей детей с особенностями развития (РАС, синдром Дауна, ТНР, ЗПР и др.). Цель — снижать родительский стресс и выгорание через:

- ежедневные микро-практики (утренний/вечерний квест, у каждого есть облегчённый «режим выживания»);
- SOS-техники для острых моментов (дыхание, заземление, самосострадание);
- дневник (форматы: «три хороших», «конверт» с отложенным открытием, «письмо другу»);
- «выговориться» голосом или текстом — с эмпатичным ответом через Azure OpenAI;
- геймификацию: «Древо резилентности», бейджи, календарь, инсайты;
- опросники, библиотеку фраз и ресурсов, подготовку к сессии со специалистом.

Заказчик — психолог, автор всего контента. Исходный черновик функционала и текстов: [docs/content_draft.docx](docs/content_draft.docx) в этом репозитории (исходное имя файла — «ПРИЛОЖЕНИЕ (1).docx»).

**Ключевой принцип — приватность.** Аудитория уязвимая. Дневник, чек-ины, записи «выговориться» хранятся только на устройстве и не должны попадать на сервер ни в каком виде. Это ограничение действует на все задачи ниже.

## 2. Репозиторий и запуск

```bash
git clone https://github.com/pototskyio-creator/volna.git
cd volna
cp lib/config/secrets.dart.example lib/config/secrets.dart   # значения — см. ниже
flutter pub get
flutter run          # устройство/симулятор; web тоже поддерживается
```

- Доступ к репозиторию: приглашение на GitHub придёт на вашу почту (напишите логин).
- **Flutter/Dart:** Dart SDK `^3.11.5`, свежий stable Flutter.
- **`lib/config/secrets.dart` в git не хранится** (в `.gitignore`). Содержит endpoint и ключ Azure OpenAI + имена деплойментов (transcribe и chat). Файл с реальными значениями передаётся отдельно по защищённому каналу — запросите у меня. Без него приложение запускается, но голосовые/чатовые функции «выговориться» не работают.
- ID приложения (Android `applicationId` и iOS bundle id): `com.pavelhegai.volna`.
  Канал распознавания речи по историческим причинам называется
  `io.volna.volna/speech` — это просто имя канала, с bundle id не связано.
- Состояние репо: один коммит от 08.06.2026, рабочее дерево чистое — это актуальная версия.

## 3. Архитектура (карта кода)

Всё приложение — в `lib/`:

| Папка | Что там |
|---|---|
| `main.dart` | Инициализация. Все storages и сервисы — глобальные `late final`, создаются до `runApp`. При падении init показывается `_FatalErrorApp`. |
| `app/router.dart` | Вся навигация, go_router, ~30 маршрутов (`/`, `/onboarding`, `/quest/morning`, `/sos/...`, `/vent...`, `/diary...`, `/tree`, `/questionnaire/:kind` и т.д.). Единая точка, чтобы понять состав экранов. |
| `features/<name>/` | Экраны по фичам: onboarding, home, quest (+survival), sos, vent, checkin, diary, tree, calendar, insights, badges, library, questionnaire, help, settings. |
| `data/content/` | **Весь контент — кодом** (Dart-структуры): quests, sos_techniques, phrases, badges, questionnaires, resources, specialists и пр. Правки текстов от заказчика обычно делаются здесь. |
| `data/local/` | Хранилища на shared_preferences: quest, checkin, diary, toolbox, badges, settings. Другой персистентности нет. |
| `services/` | `azure_chat_service`, `azure_transcribe_service` (HTTP к Azure OpenAI, ключи из secrets), `audio_recorder_service` (flutter_sound), `notification_service` (локальные пуши, flutter_local_notifications), `badges_service` (логика выдачи бейджей поверх storages). |
| `core/` | Тема (цвета/типографика — тёплая пастельная палитра, google_fonts) и общие виджеты. |

Важные факты для планирования:

- **Бэкенда нет вообще.** Никакой аналитики, аккаунтов, серверного API. Все данные локальные. Единственный внешний вызов — Azure OpenAI для транскрибации/чата.
- Состояние — без Riverpod/Bloc: глобальные storages из `main.dart` + StatefulWidget'ы.
- Тестов практически нет (заготовка в `test/`).

## 4. Задачи

### Задача 1. Правки от клиента
Список передаётся отдельным сообщением (уточняется). Большинство таких правок — тексты/логика контента в `lib/data/content/` и мелочи в экранах `features/`.

### Задача 2. Мониторинг активности пользователей + админка на VPS
Приложение сейчас ничего не отправляет, поэтому задача из трёх частей:

**2a. Бэкенд на VPS** — сервис приёма событий.
- Стек согласовать до старта (ориентир: FastAPI или Node + PostgreSQL; docker-compose приветствуется).
- Эндпоинт приёма батча событий: `{device_id (анонимный UUID, генерится приложением), event, ts, props?}`.
- Доступ к VPS (host + ssh-ключ) выдам после согласования стека.

**2b. Клиент** — отправка событий из Flutter-приложения.
- Новый сервис по образцу существующих в `lib/services/`; URL бэкенда — через `secrets.dart` или аналогичный конфиг.
- События-ориентир (по маршрутам роутера): `app_open`, `onboarding_done`, `quest_morning_done`, `quest_evening_done`, `survival_used`, `sos_opened` (+какая техника), `vent_voice_used` / `vent_text_used`, `checkin_done`, `diary_entry_created` (только факт и тип, без содержимого), `questionnaire_done` (:kind), `tree_opened`.
- Офлайн-очередь с ретраями (приложение должно полноценно работать без сети).
- **Запрещено отправлять:** тексты дневника, транскрипты и аудио «выговориться», ответы опросников, любые свободные тексты пользователя. Только факты событий.
- Переключатель в настройках «делиться анонимной статистикой» (по умолчанию — обсудим).

**2c. Веб-админка** — просмотр активности для нас и заказчика.
- Метрики: DAU/WAU, новые устройства, воронка онбординга, частота использования фич, retention по когортам.
- Доступ по логину/паролю (достаточно basic-auth или простой сессии), HTTPS.

**Готово, когда:** события с тестового устройства видны в админке; приложение без сети работает как раньше; в БД нет ни одного поля с пользовательским текстом.

### Задача 3. Тестовая выкатка
- **Android:** сборка AAB/APK, раздача тестерам — internal testing в Google Play или прямой APK.
- **iOS:** сборка и раздача через TestFlight (доступ к Apple Developer аккаунту выдам).
- Короткая инструкция для заказчика (не технарь): как установить тестовую версию на iPhone/Android.

### Задача 4. Мелкие правки по итогам теста
Придут от заказчика после задачи 3, оформлю отдельным списком.

**Порядок:** 1 → 2 → 3 → 4. Задачи 2a/2c можно вести параллельно с задачей 1.
